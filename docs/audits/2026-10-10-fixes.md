# Audit fixes implementation - October 10, 2026

Scope: F01-F13, 6.1-6.7, section 7 without practice forecasts, 8.3-8.5, 8.8 and 8.9. Practice/dummy bets were not added. This document separates source changes from evidence of operation: a passing test does not mean that the new code is already running on the server or the phone.

## Fixes

| Item | Changes |
|---|---|
| F01 | Separate attestor liveness and readiness; freshness of devnet and of the active window; the keeper stops creating rounds when oracle readiness is unconfirmed. Devnet RPC: shared cooldown, fallback and a bounded request time. Settlement, claim and withdrawal remain available. The public status additionally checks fresh readiness: a stale keeper `ready` turns into `paused` when the oracle fails; the original time is kept as `keeperUpdatedAt`. This is a scheduler and UI refusal, not an automatic change of the on-chain `paused`. |
| F02 | The install page shows the published version, date, size and SHA-256 of the APK. Android CI emits a manifest with the commit, versionCode, APK/lockfile hash and the hashes of the program files. The manifest does not certify the current program bytes on chain or any check on a device. |
| F03 | After wallet approval the original round and the exact amount are remembered; the bet is not moved and not reduced automatically (superseded on 12 October: the call is now bound to the coin and goes into the next round of the same coin, or a card offers one tap when the coin changed; see the README). If the intent has expired, the app shows that the bet was not sent. Arena is preserved when switching tabs. |
| F04 | A final round with an incomplete set of positions is rescanned; caching is allowed to complete after a full scan. |
| F05 | The mobile and web leaderboards determine freshness by `indexedAt`, separately from the publication time. A missing or invalid time is not masked. |
| F06 | A logo error is reset when the mint or image URL changes. |
| F07 | The submission texts were rewritten and the video script was corrected: detached canonical certificate, shared operator signer/keeper, upgrade/custody trust, real permissions and the limits of the evidence. The old audio must be re-recorded. |
| F08 | Wallet separates available funds, funds in play, refundable rent and device key funds for fees. The overall permission turnover is not called a loss limit. Revoke all is available outside Advanced; the separate costs and the return of rent are explained. |
| F09 | The keeper stores the raw final Position/Round data, signs the archive per wallet and per page, and confirms publication before the player account is closed. A change in a claim resets the confirmation; it is checked again before the close is sent. After a restart, it is published again. Mobile history and the friends' score are restored from the last 500 records; local data is visible immediately. History retries the restore after a network failure. |
| F10 | CI type-checks client/keeper/attestor/mobile; changes to the program and client trigger the program workflow. Android install runs only with a frozen lockfile. The APK manifest ties the build to the sources. |
| F11 | Maestro smoke flows and an Android acceptance matrix were added: device, wallet, lifecycle, pending transaction, amounts, invite, TalkBack and font sizes. Execution on a physical Seeker must be confirmed separately. |
| F12 | A critical pending bet record is required before broadcast; on error the bet is not sent. Rent-read retry with backoff, ErrorBoundary, visible history save errors, bounded local events without secrets. History saving is serialized per wallet, including a retry after a failure. |
| F13 | Repeated requests for the same price are merged; a hidden Arena does not start additional chart polls. The indexer decodes positions once and groups them by round instead of repeating a full pass. Local RPC counters and p50/p95 for RPC and confirmation in the export were added. Canonical certificates already have a separate short public cache. The shared writable Config was not changed without measuring the real bottleneck. |
| 6.1-6.2 | Before entering, TOKEN/SOL, the deferred reference and 100-160 seconds plus confirmations are explained. Before the tap, separate estimates of UP/DOWN matching and refund against the current book are shown, explicitly not guaranteed. After entering, the current match/refund and a receipt with stake/matched/unmatched/total/net are shown. |
| 6.3-6.4 | Research replay: temporal split, random/UP/DOWN/momentum/contrarian/late momentum, matching/costs/refunds and a Wilson interval. The spot manipulation model is explicitly limited. The scheduler subtracts the maximum pots of the other unfinished rounds of the same pool from the shared reserve/2500 budget; this is keeper policy, not a new on-chain cap. |
| 6.5 | One shared arena is kept; the invitation shows the next shared five-minute reference point and the friend's confirmed bet. The house does not promise a round-the-clock match. The reference point is dynamic and is not an agreed time reservation. |
| 6.6 | Session presets: 1 hour/1×, 1 day/10×, 7 days/100×; max bet 0.02/0.05/0.1 SOL. Conservative default. The choice is saved until approval; the load/save race is fixed. Top-up and extension from Wallet also go through the shared permissions form. Other active keys are not silently revoked. |
| 6.7 | Reproducible contribution calculation: matched fees minus RPC/transactions/archive/support/acquisition/house cost. The three scenarios are explicitly hypothetical; this is not a revenue forecast. |
| 7 | First entry preserves the exact intent, active positions are available, the result explains the money, a repeat names the new token/round, the invitation reflects the chain state, Wallet explains the exit. Local events cover the main steps; there is no global tracking and no measured D1/D7. |
| 8.3-8.5 | Switching between active positions; chart/clock/token follow a single selected round. A new call is separated from the observed position and is explicitly labeled. |
| 8.8-8.9 | Large font up to 150%, native fallback for pixel text, scrolling for Arena/top-up/result, main targets 48 dp, reduce motion for result animations and confetti. Storage errors no longer look like a successful send. |
