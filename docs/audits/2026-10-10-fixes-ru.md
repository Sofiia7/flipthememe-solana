# Реализация исправлений аудита — 10 октября 2026

Объём: F01–F13, 6.1–6.7, раздел 7 без учебных прогнозов, 8.3–8.5, 8.8 и 8.9. Учебные/фиктивные ставки не добавлены. Этот документ разделяет изменения исходников и доказательства эксплуатации: успешный тест не означает, что новый код уже стоит на сервере или телефоне.

## Исправления

| Пункт | Изменения |
|---|---|
| F01 | Отдельные liveness/readiness attestor; свежесть devnet и активного окна; keeper прекращает создание раундов при неподтверждённой готовности оракула. Devnet RPC: общий cooldown, fallback и ограниченное время запроса. Settlement, claim и withdrawal остаются доступными. Публичный статус дополнительно проверяет свежую readiness: старое `ready` keeper превращается в `paused` при сбое оракула; исходное время сохранено как `keeperUpdatedAt`. Это отказ планировщика и UI, не автоматическая смена on-chain `paused`. |
| F02 | Страница установки показывает опубликованную версию, дату, размер и SHA-256 APK. Android CI выдаёт manifest с commit, versionCode, APK/lockfile hash и хешами файлов программы. Manifest не удостоверяет текущие байты программы на chain или проверку устройства. |
| F03 | После wallet approval запоминается исходный раунд и точная сумма; ставка не переносится и не уменьшается автоматически. При истёкшем намерении показано, что ставка не отправлена. Arena сохраняется при переключении вкладок. |
| F04 | Финальный раунд с неполным набором positions повторно сканируется; завершение кеширования допускается после полного скана. |
| F05 | Мобильный и web leaderboard определяют свежесть по `indexedAt`, отдельно от времени публикации. Отсутствующее/некорректное время не маскируется. |
| F06 | Ошибка логотипа сбрасывается при смене mint/image URL. |
| F07 | Переписаны тексты заявки и исправлен сценарий видео: detached canonical certificate, общий оператор signer/keeper, upgrade/custody trust, реальные permissions и ограничения доказательств. Старое аудио необходимо перезаписать. |
| F08 | Wallet разделяет доступное, в игре, возвратную ренту и средства device key для комиссии. Общий оборот разрешений не называется лимитом потерь. Revoke all доступен вне Advanced; объяснены отдельные расходы и возврат ренты. |
| F09 | Keeper сохраняет сырые финальные Position/Round, подписывает архив по wallet и страницам и подтверждает публикацию до закрытия player account. Изменение claim сбрасывает подтверждение; перед отправкой close оно проверяется снова. После рестарта — повторная публикация. Мобильная история/счёт друзей восстанавливаются из последних 500 записей; локальные данные видны сразу. История повторяет восстановление при сетевом сбое. |
| F10 | CI проверяет типы client/keeper/attestor/mobile; изменения программы и client запускают program workflow. Android install только с frozen lockfile. APK manifest связывает сборку с исходниками. |
| F11 | Добавлены Maestro smoke flow и матрица Android acceptance: устройство, wallet, lifecycle, pending transaction, суммы, invite, TalkBack и размеры шрифта. Выполнение на физическом Seeker нужно подтвердить отдельно. |
| F12 | Критическая pending bet запись обязательна до broadcast; при ошибке ставка не отправляется. Retry rent-read с backoff, ErrorBoundary, видимые ошибки сохранения истории, ограниченные локальные события без секретов. |
| F13 | Повторные запросы одной цены объединяются; скрытая Arena не запускает дополнительные chart polls. Добавлены локальные счётчики RPC и p50/p95 RPC/подтверждения в экспорте. Канонические certificates уже имеют отдельный публичный краткий cache. Общий writable Config не изменён без измерения реального bottleneck. |
| 6.1–6.2 | Перед входом объяснены TOKEN/SOL, отложенный reference и 100–160 секунд + подтверждения. Показаны текущий match/возврат и receipt stake/matched/unmatched/total/net. |
| 6.3–6.4 | Исследовательский replay: temporal split, random/UP/DOWN/momentum/contrarian/late momentum, matching/costs/refunds и Wilson interval. Модель spot manipulation прямо ограничена. Планировщик вычитает максимальные банки остальных незавершённых раундов того же пула из общего reserve/2500 бюджета; это policy keeper, не новый on-chain cap. |
| 6.5 | Сохранена одна общая арена; приглашение показывает следующий общий пятиминутный ориентир и подтверждённую ставку друга. House не обещает круглосуточный match. Ориентир динамический, он не является согласованной бронью времени. |
| 6.6 | Session presets: 1 час/1×, 1 день/10×, 7 дней/100×; max bet 0.02/0.05/0.1 SOL. Консервативный default. Выбор сохраняется до approval; race загрузки/сохранения устранён. Другие активные ключи не отзываются молча. |
| 6.7 | Воспроизводимый расчёт contribution: matched fees минус RPC/transactions/archive/support/acquisition/house cost. Три сценария — явно гипотетические; это не прогноз выручки. |
| 7 | Первый вход сохраняет точное намерение, активные позиции доступны, результат объясняет деньги, повтор называет новый токен/раунд, приглашение отражает chain-состояние, Wallet объясняет выход. Локальные события покрывают основные шаги; глобального трекинга и измеренного D1/D7 нет. |
| 8.3–8.5 | Переключение активных позиций; chart/clock/token следуют одному выбранному round. Новый call отделён от наблюдаемой позиции и явно подписан. |
| 8.8–8.9 | Крупный шрифт до 150%, native fallback для pixel текста, прокрутка Arena/top-up/result, основные цели 48 dp, reduce motion для result-анимаций и confetti. Ошибки storage больше не выглядят как успешная отправка. |

## Проверка и оставшиеся внешние зависимости

Полный прогон после основной реализации: 798/798 TypeScript tests. Дополнительные тесты архива и close gating: 30/30 в целевом прогоне. Перед сборкой повторяется полный прогон и typecheck; результат сборки проверяется отдельно. Keeper bundle и Worker dry-run проходят. Android Hermes export проверяет bundle, но не заменяет native APK или устройство. Rust/on-chain layout в этой ревизии не менялся; локальный Cargo ранее заблокирован отсутствием Perl для vendored OpenSSL. Program workflow остаётся отдельным доказательством.

Для эксплуатации F01/F09 требуется поставить новый keeper на его реальный SSH-хост и каталог. Эти данные в текущем чате не предоставлены. Без них нельзя честно заявить, что production archive/close gating уже работает. Публичные RPC с 429/403 требуют доступного endpoint/квоты; fallback не создаёт квоту. Не меняем незнакомые серверы по догадке.

F02 завершён только после сборки и публикации APK из точного commit; исходники сами по себе не обновляют ссылку latest. F11/8.8 требуют прогона на физическом устройстве по `docs/android-acceptance.md`. Для 6.3/6.4 нужны реальные PumpSwap данные, измерение latency и adversarial replay; генератор отчёта не является проведённым исследованием. Для 6.7 и раздела 7 нужны реальные расходы/когорты: devnet, операторские и shadow раунды нельзя считать выручкой и удержанием пользователей.

Ни независимый аудит mainnet, ни видео, ни количественная бизнес-валидация этой ревизией не объявляются завершёнными.
